# 开发指南

Relay 使用 Rust + Tauri 2 构建桌面应用，界面采用 React、TypeScript 和 Vite。当前开发目标为 Windows。

## 环境准备

- Node.js 22.22.2+（或满足依赖要求的更新 LTS 版本）与 npm。
- Rust MSVC 工具链。
- Visual Studio C++ Build Tools。
- Microsoft Edge WebView2 Runtime。
- 本机 Codex 安装及登录配置，用于运行实际会话。

Relay 在未手动指定路径时自动查找 Codex，覆盖：

- 当前 PATH，以及 Windows 用户／系统注册表中持久化的 PATH。
- `%LOCALAPPDATA%/OpenAI/Codex/bin/<版本目录>/codex.exe` 与已知桌面资源目录。
- npm 全局安装、nvm／pnpm 的常见目录和配置的 Volta 安装目录。
- 当前用户的 VS Code、VS Code Insiders、Cursor 和 Windsurf 中官方 Codex 扩展的 CLI。
- 用户的 `.cargo/bin`、`.local/bin` 和 Scoop／WinGet 常见入口。

设置里的“自动检测”会显示找到的路径和来源，成功后恢复路径留空的自动模式；点击“完成”保存。扫描只读取已知目录，不启动 Codex 或遍历整块磁盘。自动检测失败时仍可手动选择 `codex.exe`、`codex.js` 或 npm 的 `codex.cmd/ps1`；npm 启动脚本会解析到实际入口，优先使用原生二进制，只有 JavaScript 入口时才需要 Node.js。

应用不会自动安装或登录 Codex，也不会接管官方桌面应用内置的私有进程。

## 启动桌面应用

在仓库根目录执行：

```powershell
npm install
npm run desktop
```

Tauri 会启动 Vite 开发服务器和 Rust 桌面进程。

## 预览界面

```powershell
npm run dev
```

浏览器预览只展示界面与空状态，不连接本机或远端 Codex。设备配对、系统凭据和 Agent 操作需要在 Tauri 桌面应用中使用。

## 构建与测试

在仓库根目录执行：

```powershell
npm run build
npm test
cargo test --workspace
```

前端与 Workers 的回归测试由根目录的 Vitest 统一运行，覆盖缓存淘汰、流式事件合并、异步响应过期、审批竞态和注册端替换。Rust 测试覆盖请求取消、完整写入、连接背压、握手及加密分片。

中继可单独执行类型检查和打包预演，不会部署到 Cloudflare：

```powershell
npm --prefix workers/relay ci
npm --prefix workers/relay run build
```

工作台最多保留 24 个完整会话缓存，估算内存预算为 48 MiB；正在查看的会话会保留，单个会话超过预算时也不会截断其内容。缓存淘汰后重新打开会话会重新读取历史。流式事件按帧合并，仅保存回合更新序号，不长期保存原始事件。

## Windows 打包

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content -LiteralPath "$env:USERPROFILE/.tauri/agent-relay-updater.key" -Raw
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "" # 若密钥设置了密码，使用对应密码
npm run bundle
```

当前配置生成 NSIS 安装包，输出目录为：

```text
target/release/bundle/nsis/
```

Rust workspace 位于仓库根目录。安装包尚未配置代码签名证书。Mac/Linux 的部分平台适配保留在源码中，但当前不提供对应的发布配置。

公开发布前，在仓库根目录的 PowerShell 中重映射编译路径，避免程序包含本机用户名和源码绝对路径：

```powershell
$relaySourceRoot = (Get-Location).Path
$env:CARGO_ENCODED_RUSTFLAGS = @(
  "--remap-path-prefix=$env:USERPROFILE=/build/user",
  "--remap-path-prefix=$relaySourceRoot=/build/agent-relay"
) -join [char]0x1f
npm run bundle
```

该命令会使 Cargo 使用新的编译参数重新构建依赖。发布时附上安装包和 SHA-256 校验文件；不要将登录、设备配置或配对链接加入仓库与 Release。

## 自动更新与发布

桌面端通过 Rust 的 `tauri-plugin-updater` 检查、下载和验证更新。`src-tauri/src/updater.rs` 保存更新状态，使用 `relay:update` 事件同步前端；`src/updates.ts` 调度启动后和每 6 小时的检查，设置页提供手动入口。下载、检查和安装共用操作锁，重复点击不会创建并行下载；关闭设置页后仍会显示下载状态。安装前通过 Host 请求锁阻止新的本机及远端操作，并确认没有运行回合、待处理审批或正在进行的请求，再保存设置并交给安装器。Windows 安装退出路径显式关闭 Relay 管理的 Codex 和设备连接。

配置中的 `bundle.createUpdaterArtifacts = true` 生成 NSIS 更新签名；`plugins.updater.pubkey` 使用本机既有公钥。私钥位于 `%USERPROFILE%/.tauri/agent-relay-updater.key`，不会提交到仓库。正式打包需要设置 `TAURI_SIGNING_PRIVATE_KEY`，加密私钥还需要对应的 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。请保留这把密钥的备份，之后的版本必须继续使用同一把签名密钥。

更新清单地址为：

```text
https://github.com/beiyuan324/agent-relay/releases/latest/download/latest.json
```

配置要求 HTTPS、有效安装包签名和签名中的版本与清单版本一致，拒绝旧版本回退。Tauri CLI 固定在支持版本签名的 `~2.12.4` 系列。前端只调用本机命令，不开放 updater 插件的直接安装权限给网页，也不向远端设备暴露更新命令。

`.github/workflows/release.yml` 在推送 `v*` 标签或手动指定既有标签时构建 Windows NSIS 包，使用仓库 Actions secrets 中的 `TAURI_SIGNING_PRIVATE_KEY` 与可选的 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 签名。工作流只创建草稿 Release；生成并上传安装包、`.sig`、`latest.json` 和 `SHA256SUMS.txt` 后，发布草稿即可让正式安装版发现更新。没有签名私钥时发布会失败，不会生成跳过验证的更新包。

发布新版本时：

1. 同步修改 `package.json`、`package-lock.json` 的根版本、`Cargo.toml` 的 workspace 版本及 `src-tauri/tauri.conf.json` 的版本；同步 Cargo 锁文件中的本项目包版本。
2. 将对应提交推送后创建 `v<版本号>` 标签并推送，或对已有标签运行 Release Windows 工作流。标签必须与应用三个版本来源完全一致。
3. 查看草稿 Release 中的安装包、签名和更新清单，确认后正式发布。保持为普通 Release；预发布不会成为 `releases/latest` 更新来源。
4. 首个包含更新功能的版本仍需要手动安装一次。之后的已安装版本会读取最新清单并升级。

仅需源码开发时使用 `npm run desktop`，不会检查或安装更新；浏览器预览同样不会连接更新服务。

## 项目结构

```text
agent-relay/
├── crates/relay-core/     # 加密、连接、双向控制与 Codex 适配
├── src-tauri/            # 桌面命令、系统凭据、设置与打包
├── src/                  # React 工作台与交互
├── public/               # 应用静态资源
├── workers/relay/        # Cloudflare Workers 中继
└── docs/                 # 使用、部署和开发指南
```

### Rust 内核

| 文件 | 职责 |
| --- | --- |
| `crypto.rs` | relay-e2e/v1 密钥派生、握手确认、加密与防重放 |
| `net.rs`、`tunnel.rs` | 局域网 WebSocket 与 Workers 隧道 |
| `host.rs` | 设备信任、共享状态、双向请求与连接恢复 |
| `codex.rs` | app-server 进程、会话、事件与审批 |
| `discovery.rs` | Codex 安装位置、npm 原生入口和 Windows PATH 检测 |
| `remote.rs`、`relay.rs` | 加密控制消息、分片与配对邀请 |
| `model.rs` | 设备、设置与消息类型 |

连接层负责配对、加密与双向请求；Codex 适配层负责 stdio 会话与审批；Tauri 层提供桌面命令、系统凭据和窗口能力。界面中的设备及会话状态始终按执行电脑隔离。

## 设置与凭据

普通设置保存为 `settings.json`，系统配置根目录由 Tauri 的路径解析器按当前用户确定，沿用既有子目录：Windows 为 `agent-relay/Relay/config`，macOS 为 `app.agent-relay.Relay`，Linux 为 `relay`。

配对密钥通过系统凭据管理器存储，服务名为 `app.agent-relay.desktop`，凭据名称使用每对设备的 UUID，不写入设置文件。各电脑独立维护 Codex 登录、设备信任与共享状态。
